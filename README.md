# Оптовый подсчёт

Веб-приложение для магазина HardSmoke: оператор вносит собранные заказы, указывает сборщиков и видит дневные и месячные итоги. Проект разработан пользователем Shamrik. Приложение работает локально и может быть размещено на VPS или другом хостинге с поддержкой Python.

## Запуск

Требуется Python 3.13 или совместимая версия. Из корня проекта:

```powershell
python server.py
```

Откройте http://localhost:8000. Сервер должен оставаться запущенным, пока используется приложение. Фреймворки и сборщик не используются: браузер получает статические `index.html`, `styles.css` и `app.js` непосредственно от `server.py`. По умолчанию сервер слушает только `127.0.0.1`; адрес и порт можно изменить переменными `HOST` и `PORT`.

## Размещение на хостинге

Подойдет VPS или PaaS с Python 3.13, постоянным диском и возможностью запустить долгоживущий процесс. Для публичного сайта рекомендуется VPS + Nginx + HTTPS. Обычный статический хостинг без запуска Python-сервера не подойдет.

### Быстрый запуск на VPS

Пример для Ubuntu/Debian. Команды выполняются на сервере после установки Python 3.13 и Git:

```bash
git clone https://github.com/shamraywork-afk/opt_calculator.git
cd opt_calculator
python3 -m py_compile server.py
HOST=127.0.0.1 PORT=8000 python3 server.py
```

Сервер доступен внутри VPS на `127.0.0.1:8000`. Для постоянной работы создайте `/etc/systemd/system/opt-calculator.service`:

```ini
[Unit]
Description=Opt calculator
After=network.target

[Service]
WorkingDirectory=/var/www/opt_calculator
ExecStart=/usr/bin/python3 server.py
Environment=HOST=127.0.0.1
Environment=PORT=8000
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

Запустите службу:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now opt-calculator
sudo systemctl status opt-calculator
```

Настройте Nginx на проксирование домена в `127.0.0.1:8000`:

```nginx
server {
  server_name example.com;

  location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
```

После настройки DNS и Nginx включите HTTPS, например через Certbot:

```bash
sudo certbot --nginx -d example.com
```

### Первичная настройка на хостинге

1. Не загружайте в репозиторий локальные `admin.json` и `orders.json`. Они исключены через `.gitignore`.
2. Создайте отдельную папку приложения на сервере и выдайте процессу права записи в нее: сервер должен создавать и изменять `admin.json` и `orders.json`.
3. Запустите приложение и откройте домен. При отсутствии `admin.json` появится форма первичной регистрации единственного администратора.
4. Зарегистрируйте аккаунт, затем используйте обычный вход. Пароль хранится только в виде PBKDF2-хеша.
5. Настройте резервное копирование `orders.json` и `admin.json`. Потеря `admin.json` позволит пройти регистрацию заново, а потеря `orders.json` удалит журнал заказов.

Встроенный HTTP-сервер Python подходит для небольшого внутреннего приложения за Nginx. Для большого количества пользователей перед публикацией потребуется полноценный production WSGI/ASGI-сервер, база данных и ограничение доступа.

## Структура

- `server.py` - HTTP-сервер на стандартной библиотеке Python, API заказов, авторизация, запись данных и настройка `HOST`/`PORT`.
- `index.html` - разметка журнала, формы нового заказа, вкладки месяца, окна входа, редактирования и личного кабинета.
- `admin.html` - отдельная страница `/admin` для первичной регистрации и входа администратора.
- `admin.js` - логика страницы `/admin`; допускает только админскую роль и после входа возвращает в журнал.
- `app.js` - состояние интерфейса, загрузка данных, рендеринг, расчеты, обработчики форм и модальных окон.
- `styles.css` - визуальная система, адаптивная верстка и анимации модальных окон.
- `orders.json` - локальное хранилище заказов; создается или обновляется сервером и не коммитится в Git.
- `admin.json` - локальное хранилище единственного админ-аккаунта с солью и хешем пароля; создается при первой регистрации и не коммитится в Git.
- `users.json` - локальное хранилище пользователей-сборщиков с солью и хешами паролей; создается администратором и не коммитится в Git.
- `.gitignore` - исключает `orders.json`, `__pycache__` и `.pyc`.

## Модель заказа

Каждая запись в `orders.json` имеет вид:

```json
{
  "id": "202609041",
  "number": "192467",
  "date": "2026-09-04",
  "client": "Название клиента",
  "note": "Комментарий",
  "count": 10,
  "pickers": ["Имя сборщика"]
}
```

`number`, `date`, `count` и минимум один сборщик обязательны в интерфейсе. Сервер дополнительно проверяет, что `count >= 1`, а массив `pickers` содержит ровно одного или двух человек. `id` сохраняется при редактировании: наличие такого `id` заменяет запись, отсутствие добавляет новую в начало списка.

## Правила расчетов

- Дневной журнал фильтруется по `state.filterDate`.
- Вкладка «Месяц» всегда показывает записи текущего месяца по ISO-префиксу `YYYY-MM`.
- Если у заказа один сборщик, ему начисляется весь `count`.
- Если сборщиков двое, каждому начисляется `Math.ceil(count / 2)`. Поэтому сумма начислений при нечетном количестве может быть больше количества товара в заказе.
- Месячная общая сумма показывает фактическую сумму `count`, а рейтинг показывает начисленные позиции каждого сборщика.
- Все пользовательские строки при выводе в HTML проходят через `escapeHtml`.

## API

Сервер слушает `HOST:PORT` (по умолчанию `127.0.0.1:8000`):

- `GET /api/orders` - получить все заказы. Просмотр доступен без входа.
- `GET /admin` - отдельная страница регистрации и входа администратора.
- `GET /api/auth` - проверить текущую сессию.
- `POST /api/login` - вход с JSON `{ "login": "...", "password": "..." }`; при успехе сервер выдает HttpOnly cookie `session`.
- Для входа администратора через `/admin` клиент передает `admin_only: true`; обычный пользователь получает отказ `403`.
- `POST /api/register` - первичная регистрация единственного админ-аккаунта с тем же JSON; работает только пока `admin.json` не существует.
- `POST /api/users` - добавить пользователя-сборщика; требуется роль администратора.
- `POST /api/profile` - сохранить аватар администратора как data URL изображения до 500 КБ; требуется роль администратора.
- `POST /api/logout` - завершить текущую сессию.
- `POST /api/orders` - добавить или заменить заказ; требуется авторизация.
- `DELETE /api/orders/{id}` - удалить один заказ; требуется авторизация.
- `POST /api/orders/clear` - очистить диапазон; требуется авторизация. JSON: `{ "scope": "day|month|all", "period": "YYYY-MM-DD|YYYY-MM|" }`.

Изменяющие маршруты должны проверять `require_auth()` на сервере. Одного скрытия или отключения кнопок во фронтенде недостаточно. Сессии хранятся в памяти процесса и становятся недействительными после перезапуска сервера.

## Логика интерфейса

`app.js` хранит заказы в `state.orders`, выбранную дату в `state.filterDate` и состояние входа в `state.authenticated`. После любого успешного изменения вызывается `loadOrders()`, который обновляет журнал, метрики и месячный рейтинг.

Основные UI-сценарии:

1. При отсутствии `admin.json` страница `/admin` показывает форму «Первичная регистрация». Нужно указать логин и пароль минимум из 6 символов и повторить пароль.
2. После успешной регистрации создается единственный админ-аккаунт, пользователь автоматически входит в систему, а повторная регистрация блокируется сервером.
3. При наличии `admin.json` страница `/admin` открывает авторизацию администратора. Пароль проверяется по PBKDF2-хешу, исходный пароль не сохраняется. Кнопка «Войти» на главной странице используется для обычных пользователей.
4. Гость может просматривать журнал и месячную статистику, но форма ввода и кнопки изменения отключены.
5. Администратор видит кнопку «Кабинет», может добавить заказ, редактировать и удалять его, очищать записи, загружать аватар и вручную создавать пользователей-сборщиков.
6. В кабинете администратор задает аватар файлом PNG, JPG или WebP до 500 КБ. Изображение сохраняется в профиле администратора как data URL.
7. Администратор добавляет сборщиков вручную, указывая логин и пароль минимум из 6 символов. Повторяющиеся логины запрещены.
8. Обычный пользователь-сборщик может только добавлять новые заказы. Сервер запрещает ему редактирование, удаление и очистку, даже при прямом обращении к API.
9. Кабинет открывается поверх страницы. В нем есть выход и очистка записей за день, текущий месяц или все время. Очистка требует подтверждения и выполняется через сервер.
10. Администратор в кабинете может задать начало и окончание рабочего месяца. Диапазон может переходить между календарными месяцами, например `25.08–24.09`; у сборщика эта настройка скрыта.
11. Рейтинг и сумма на вкладке «Месяц» учитывают заказы между этими датами включительно. Период по умолчанию: с первого дня текущего календарного месяца по текущую дату.
12. Выбранный рабочий период сохраняется в `localStorage` браузера и не влияет на данные заказов или других пользователей.
13. Окна входа, кабинета и редактирования закрываются кнопкой, кликом по фону или клавишей `Esc`.

## Правила доработки

- Сохраняйте текущий стек: стандартный Python и vanilla JavaScript без лишних зависимостей.
- При изменении формата заказа обновляйте одновременно серверную валидацию, HTML-поля, сбор payload и расчеты в `app.js`.
- Любую операцию записи или удаления защищайте на сервере, даже если соответствующая кнопка скрыта для гостя.
- Проверяйте роль на сервере: обычному пользователю разрешено только создание заказа без `id`; операции с существующим `id`, удаление, очистка, добавление пользователей и изменение профиля доступны только администратору.
- Не добавляйте `orders.json`, `admin.json` и `users.json` в Git: это локальные данные конкретного компьютера.
- Перед публикацией проекта удалите локальный `admin.json`, если он существует. Благодаря этому новый пользователь увидит форму первичной регистрации. Не удаляйте рабочий `admin.json` на действующем сервере без резервной копии.
- Не заменяйте `id` при редактировании, иначе вместо изменения появится дубликат.
- Для новых пользовательских значений используйте `escapeHtml` перед вставкой в `innerHTML`.
- Для месячных отчетов сравнивайте ISO-строки дат (`YYYY-MM-DD`) включительно, чтобы корректно поддерживать период через границу календарного месяца.
- Для проверки запуска используйте `python -m py_compile server.py`, затем откройте http://localhost:8000 и проверьте вход, редактирование, удаление и очистку.
