# Оптовый подсчёт

Локальное веб-приложение для магазина HardSmoke: оператор вносит собранные заказы, указывает сборщиков и видит дневные и месячные итоги. Проект разработан пользователем Shamrik.

## Запуск

Требуется Python 3.13 или совместимая версия. Из корня проекта:

```powershell
python server.py
```

Откройте http://localhost:8000. Сервер должен оставаться запущенным, пока используется приложение. Фреймворки и сборщик не используются: браузер получает статические `index.html`, `styles.css` и `app.js` непосредственно от `server.py`.

## Структура

- `server.py` - HTTP-сервер на стандартной библиотеке Python, API заказов, авторизация и запись данных.
- `index.html` - разметка журнала, формы нового заказа, вкладки месяца, окна входа, редактирования и личного кабинета.
- `app.js` - состояние интерфейса, загрузка данных, рендеринг, расчеты, обработчики форм и модальных окон.
- `styles.css` - визуальная система, адаптивная верстка и анимации модальных окон.
- `orders.json` - локальное хранилище заказов; создается или обновляется сервером и не коммитится в Git.
- `admin.json` - локальное хранилище единственного админ-аккаунта с солью и хешем пароля; создается при первой регистрации и не коммитится в Git.
- `.gitignore` - исключает `orders.json`, `__pycache__` и `.pyc`.

## Модель заказа

Каждая запись в `orders.json` имеет вид:

```json
{
  "id": "202609041",
  "number": "192467",
  "date": "2026-09-04",
  "client": "Название клиента",
  "note": "Комментарий",
  "count": 10,
  "pickers": ["Имя сборщика"]
}
```

`number`, `date`, `count` и минимум один сборщик обязательны в интерфейсе. Сервер дополнительно проверяет, что `count >= 1`, а массив `pickers` содержит ровно одного или двух человек. `id` сохраняется при редактировании: наличие такого `id` заменяет запись, отсутствие добавляет новую в начало списка.

## Правила расчетов

- Дневной журнал фильтруется по `state.filterDate`.
- Вкладка «Месяц» всегда показывает записи текущего месяца по ISO-префиксу `YYYY-MM`.
- Если у заказа один сборщик, ему начисляется весь `count`.
- Если сборщиков двое, каждому начисляется `Math.ceil(count / 2)`. Поэтому сумма начислений при нечетном количестве может быть больше количества товара в заказе.
- Месячная общая сумма показывает фактическую сумму `count`, а рейтинг показывает начисленные позиции каждого сборщика.
- Все пользовательские строки при выводе в HTML проходят через `escapeHtml`.

## API

Сервер слушает `localhost:8000`:

- `GET /api/orders` - получить все заказы. Просмотр доступен без входа.
- `GET /api/auth` - проверить текущую сессию.
- `POST /api/login` - вход с JSON `{ "login": "...", "password": "..." }`; при успехе сервер выдает HttpOnly cookie `session`.
- `POST /api/register` - первичная регистрация единственного админ-аккаунта с тем же JSON; работает только пока `admin.json` не существует.
- `POST /api/logout` - завершить текущую сессию.
- `POST /api/orders` - добавить или заменить заказ; требуется авторизация.
- `DELETE /api/orders/{id}` - удалить один заказ; требуется авторизация.
- `POST /api/orders/clear` - очистить диапазон; требуется авторизация. JSON: `{ "scope": "day|month|all", "period": "YYYY-MM-DD|YYYY-MM|" }`.

Изменяющие маршруты должны проверять `require_auth()` на сервере. Одного скрытия или отключения кнопок во фронтенде недостаточно. Сессии хранятся в памяти процесса и становятся недействительными после перезапуска сервера.

## Логика интерфейса

`app.js` хранит заказы в `state.orders`, выбранную дату в `state.filterDate` и состояние входа в `state.authenticated`. После любого успешного изменения вызывается `loadOrders()`, который обновляет журнал, метрики и месячный рейтинг.

Основные UI-сценарии:

1. При отсутствии `admin.json` кнопка «Войти» открывает форму «Первичная регистрация». Нужно указать логин и пароль минимум из 6 символов и повторить пароль.
2. После успешной регистрации создается единственный админ-аккаунт, пользователь автоматически входит в систему, а повторная регистрация блокируется сервером.
3. При наличии `admin.json` кнопка «Войти» открывает обычную авторизацию. Пароль проверяется по PBKDF2-хешу, исходный пароль не сохраняется.
4. Гость может просматривать журнал и месячную статистику, но форма ввода и кнопки изменения отключены.
5. Авторизованный пользователь видит кнопку «Кабинет», может добавить заказ, открыть заказ через кнопку редактирования или удалить его.
6. Кабинет открывается поверх страницы. В нем есть выход и очистка записей за день, текущий месяц или все время. Очистка требует подтверждения и выполняется через сервер.
7. Окна входа, кабинета и редактирования закрываются кнопкой, кликом по фону или клавишей `Esc`.

## Правила доработки

- Сохраняйте текущий стек: стандартный Python и vanilla JavaScript без лишних зависимостей.
- При изменении формата заказа обновляйте одновременно серверную валидацию, HTML-поля, сбор payload и расчеты в `app.js`.
- Любую операцию записи или удаления защищайте на сервере, даже если соответствующая кнопка скрыта для гостя.
- Не добавляйте `orders.json` и `admin.json` в Git: это локальные данные конкретного компьютера.
- Перед публикацией проекта удалите локальный `admin.json`, если он существует. Благодаря этому новый пользователь увидит форму первичной регистрации.
- Не заменяйте `id` при редактировании, иначе вместо изменения появится дубликат.
- Для новых пользовательских значений используйте `escapeHtml` перед вставкой в `innerHTML`.
- Для проверки запуска используйте `python -m py_compile server.py`, затем откройте http://localhost:8000 и проверьте вход, редактирование, удаление и очистку.
